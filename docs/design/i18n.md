# PasswordVault: localisation plan and four-language glossary

Date 2026-10-06. Status: proposal for review. Scope: the languages of the app's screens — English, Uzbek in Latin script, Uzbek in Cyrillic script and Russian — on Android 7.0 to 17 (API 24–37): resource layout, how Android chooses a language, the in-app language switch, the Uzbek alphabet question, a sourced glossary, writing rules and tests. The English wording of each screen belongs to [ux.md](ux.md); this document fixes how that wording is translated, stored and tested. Search behaviour is specified in ux.md §5.11 and refined in §2.7 here.

**Revised on 2026-10-06** by build-plan package 0.3: the glossary (§3) gains the lock's new terms that lock.md §16.3 asks for, with term 58 worded "tries" and term 59 kept for the master-password wait, and "Copied text" of architecture.md D-25 (section I); §1.4.6 gains the plan for overriding library strings in Ўзбекча (package 6.3).

How I know things: **[V]** checked today in the named primary source (AOSP branch `android17-release` unless another tag is named; bytecode of the named AAR or jar; CLDR; lex.uz; the cited web page); **[X]** my own experiment today (in the session scratchpad `i18n/lang/`: an AGP 9.4.1 test app, ICU4J 78.1 and 56.1 probes, a scan of AOSP's and five password managers' string files, a tested search-folding function); **[I]** my judgement or inference; **[N]** needs review by a native speaker.

## 0. Decisions in brief

1. **Four languages in version 1, each complete**: English `values/` (default), Uzbek Latin `values-uz/`, Uzbek Cyrillic `values-b+uz+Cyrl/`, Russian `values-ru/`. The user asked for "uzbek latin cyrilic, english, russian", so Cyrillic Uzbek is not "only on request" as ux.md §9 currently says.
2. **The app has its own language switch** (Settings › Language, and a globe button on the first screen): *System language · Oʻzbekcha · Ўзбекча · English · Русский*. On Android 13 and later the phone's Settings › Apps › PasswordVault › Language shows the same four languages.
3. **Mechanism**: `AppCompatDelegate.setApplicationLocales` from appcompat 1.8.0; `MainActivity : AppCompatActivity` (which is a `FragmentActivity`, so `BiometricPrompt` keeps working) with a `Theme.AppCompat` window theme; the `AppLocalesMetadataHolderService` entry with `autoStoreLocales` for Android 7–12; `generateLocaleConfig = true` with `unqualifiedResLocale=en` (works in AGP 9.4.1 [X]); `localeFilters` limited to our four languages.
4. **Do not rely on the phone's own language for Uzbek Cyrillic.** AOSP has let users add Uzbek (Cyrillic) since Android 7.0 (shown as "Ўзбек (Кирил)" with Android 7's ICU 56 and "Ўзбекча (Кирил)" with Android 17's ICU 78 [X]), but Android itself has no Cyrillic Uzbek translation, and no manufacturer documents it.
5. **Uzbek Latin is written in the 1995 alphabet, which is the law today**: oʻ and gʻ with U+02BB, the tutuq belgisi ʼ with U+02BC — as in nearly every Uzbek string Google has added to Android since Android 13 (590 of 595 in Settings), in Google Search and in Firefox. The 2026 reform (Ö, Ğ, Ş, Ç) passed both chambers of parliament but was not signed by today; it would apply six months after publication. Our screens change only when the reform is in force *and* Android's own Uzbek changes. Search accepts both spellings now.
6. **Uzbek Cyrillic follows today's official Cyrillic usage** (lex.uz, my.gov.uz): "Парол", "паролни" without a soft sign; е or э by position; ъ for ʼ.
7. **Search** reduces apostrophe variants, ö ğ ş ç, Uzbek and Russian Cyrillic, and ё/е to one key (reference function, all 61 test cases pass [X]). Sorting uses ICU collation after the apostrophes are made uniform.
8. **Writing**: sentence case; Uzbek *siz* and polite imperatives ("kiriting"); Russian *вы* in lower case; quotation marks “ ” in Uzbek and « » in Russian; a real ellipsis …; a no-break space between a number and its word; Russian ё always written.
9. **Plurals** with `<plurals>` and `pluralStringResource`: Russian one/few/many/other, Uzbek and English one/other (Uzbek uses the same text in both).
10. **Space**: plan for +25 % on short labels and up to 2.6 times on the longest; Android cannot hyphenate Uzbek.
11. **Dates and numbers** come from `android.icu` with the app's language: 6-okt, 2026 · 6 окт, 2026 · 6 окт. 2026 г. · 1 234 567,89 · 24-hour clock.
12. **Tests**: lint errors for missing translations and plurals, plus our own completeness test for `values-b+uz+Cyrl`, because lint does not check that folder [X]; an apostrophe and script checker; pseudo-locales; one screenshot per screen and language; a device matrix for API 24, 28, 32, 33 and 37.

## 1. Android setup (API 24–37)

### 1.1 Resource directories

| Directory | Content | Why |
|---|---|---|
| `res/values/` | English, the default | Every string exists here. `res/resources.properties` contains `unqualifiedResLocale=en` (needed by `generateLocaleConfig`) |
| `res/values-uz/` | Uzbek, Latin script | The directory AOSP and the androidx libraries we use (appcompat, Compose, biometric) use for Uzbek [V]. Android computes the script Latn for `uz` and for `uz-UZ` (likely-script table, `libs/androidfw/LocaleDataLookup.cpp:6450` `uz -> Latn`; the same entry is in `android-7.0.0_r1` `LocaleDataTables.cpp:760`) [V] |
| `res/values-b+uz+Cyrl/` | Uzbek, Cyrillic script | BCP 47 qualifier (API 21+). No AOSP or androidx module ships this directory [V] |
| `res/values-ru/` | Russian | |
| `res/values/donottranslate.xml` | Language names (each in its own language) and brand names | `translatable="false"` |

Not used: `values-uz-rUZ`, `values-b+uz+Latn`, `values-ru-rRU` — the region adds nothing, because Android matches language and script; Arabic-script Uzbek (`uz-Arab-AF`) is out of scope.

Module `build.gradle.kts` (every line compiled and ran in an AGP 9.4.1 / Gradle 9.6.0 test app [X]):

```kotlin
android {
    androidResources {
        generateLocaleConfig = true                              // res/xml/_generated_res_locale_config.xml + manifest attribute
        localeFilters += listOf("en", "uz", "b+uz+Cyrl", "ru")  // drop the other languages androidx brings
    }
    buildTypes {
        debug { isPseudoLocalesEnabled = true }                  // en-XA and ar-XB for testing
    }
    bundle {
        language { enableSplit = false }                         // only matters if we ever ship an App Bundle (§1.4.6)
    }
    lint {
        error += listOf("MissingTranslation", "ExtraTranslation", "MissingQuantity",
                        "StringFormatMatches", "StringFormatInvalid", "TypographyEllipsis")
    }
}
```

**Why `localeFilters` matters [X].** Without it the test APK contained 88 locales (af … zu, Kazakh `kk` and Kyrgyz `ky` among them), almost all from androidx. Android treats every locale present in the APK as one the app supports (`ResourcesImpl.java:548`, `getNonSystemLocales()`), so a phone set to Kazakh then Russian would choose Kazakh: androidx's own texts in Kazakh, ours in English. With the filter the release APK contains only `ru`, `uz`, `uz-Cyrl` and the default, and the same phone gets Russian.

### 1.2 How Android 7 to 17 chooses the resources

Android decides in two steps; the code is the same in `android-7.0.0_r1` and `android17-release` [V]:

1. **Choose one locale from the user's list** (`ResourcesImpl.updateConfiguration`, `ResourcesImpl.java:544–573`). When the phone has more than one language, Android takes the locales contained in the APK and calls `LocaleList.getFirstMatchWithEnglishSupported()` (`LocaleList.java:403–439`). That returns the first language in the user's list whose *language and likely script* equal one of the app's locales (`matchesLanguageAndScript`, `LocaleList.java:365`; the script comes from ICU `addLikelySubtags`). English counts as supported because the default resources are assumed to be English. If nothing matches, the first locale in the list stays. With a single phone language this step is skipped (`computeFirstMatchIndex` returns 0 at once).
2. **Find the directory** (`ResTable_config::match`, `ResourceTypes.cpp:2986`). A `values-*` directory matches only if the language is equal and the scripts are equal; a directory without a script gets its likely script (`uz` → Latn, `uz-AF` → Arab, `uz-CN` → Cyrl, `ru` → Cyrl). If no locale directory matches, `values/` is used. Android never falls back to a different language's directory.

**Android 15 and later**, one extra path: when the app's locale config sets `android:defaultLocale` (attribute added in API 35 [V `api-versions.xml`]) and the user has more than one language, `ContextImpl.java:3870` hands the config to the resources, and a string missing in the chosen language can then come from another of the user's languages (`AssetManager2.cpp:828`). AGP 9.4.1 writes `android:defaultLocale` only into `xml/_generated_res_locale_config.xml` and leaves it out of the `xml-v35/` copy [X], so this path stays off and Android 7 to 17 behave alike. Keep it that way: a hand-written config with `defaultLocale` could mix languages on one screen [I].

What a phone shows, simulated with the AOSP algorithm and ICU4J 78.1, the ICU version of `android17-release` [X] (not run on a device):

"ru-UZ" cannot be chosen in the phone's picker — AOSP lists Russian only for BY, EE, KG, KZ, LT, LV, MD, PL, RU and UA [V `locale_config.xml`] — but it would also reach `values-ru`.

### 1.3 Can the user choose Uzbek Cyrillic as the phone's language?

- **AOSP, Android 7.0 to 17: yes, but untranslated.** `uz-Cyrl-UZ` (and `uz-Latn-UZ`, `uz-Arab-AF`) is in `frameworks/base/core/res/res/values/locale_config.xml` in every release I checked: 7.0.0, 7.1.1, 8.0.0, 9, 10, 11, 12, 13, 14, 15, 16 and `android17-release` (ICU 78.1, CLDR 48) [V]. The Settings "Add a language" picker passes `translatedOnly = false` (`android-7.0.0_r1` `LocaleListEditor.java:249`; `android17-release` `LocalePickerWithRegionActivity.java:90`), so untranslated languages are offered [V]. Android's own strings exist only in `values-uz` (Latin) — `frameworks/base/core/res/res` has no Cyrillic Uzbek directory [V] — so the phone's menus stay in another language while apps that ship Cyrillic Uzbek use it.
- **Manufacturers can hide languages**: `LocalePicker.getSupportedLocales()` applies the regular expression in the system property `ro.localization.locale_filter` (`LocalePicker.java:102–138`) [V].
- **Pixel**: uses AOSP Settings; I found no public statement of a filter. Not tested: no device, and the emulators are reserved for other work.
- **Samsung (One UI) and Xiaomi (HyperOS)**: their own language pickers; I found no manufacturer document listing Uzbek in Cyrillic script (Samsung's Uzbek support page on changing the system language gives no list) [V searched]. Treat as unavailable [I].
- **Apple (for comparison)**: Apple's iOS feature-availability page lists Uzbek (Arabic, Cyrillic, Latin) only under QuickType keyboards, not as a system language [V].

So the in-app switch is the only dependable way for a Cyrillic-Uzbek reader to get Cyrillic, on every phone and version.

### 1.4 The in-app language switch

#### 1.4.1 Library, activity and theme

- **appcompat 1.8.0** is the newest stable release on Google Maven today (versions 1.7.1, 1.8.0-alpha01, 1.8.0-rc01, 1.8.0) [V `maven-metadata.xml`]. Its POM asks for activity 1.8.0, fragment 1.5.4 and core 1.13.0; our newer activity 1.13.0 and core 1.19.1 win resolution [V POM]. Its manifest declares nothing (`minSdkVersion 23`) [V AAR].
- **`class MainActivity : AppCompatActivity()`**. `AppCompatActivity extends FragmentActivity` [V javap], so the classic `BiometricPrompt(FragmentActivity, …)` constructor (platform.md §3.10) works unchanged. Android's guide: AppCompatActivity is required for the backward-compatible per-app language API [V DAC].
- **Window theme must descend from `Theme.AppCompat`**, e.g. `<style name="Theme.PasswordVault" parent="Theme.AppCompat.DayNight.NoActionBar">`. Compose's `setContent` goes through `AppCompatActivity.setContentView`, which throws "You need to use a Theme.AppCompat theme (or descendant) with this activity." otherwise [V string in `AppCompatDelegateImpl.createSubDecor`]. Colours and typography still come from Compose's `MaterialTheme`.

#### 1.4.2 Manifest

```xml
<application android:theme="@style/Theme.PasswordVault" ...>
    <activity android:name=".MainActivity" android:exported="true"> ... </activity>

    <!-- Lets AppCompat remember the choice itself on Android 7–12. -->
    <service
        android:name="androidx.appcompat.app.AppLocalesMetadataHolderService"
        android:enabled="false"
        android:exported="false">
        <meta-data android:name="autoStoreLocales" android:value="true" />
    </service>
</application>
```

`android:localeConfig="@xml/_generated_res_locale_config"` is added to the merged manifest by AGP [X]; do not write it by hand, and do not add a hand-written `locales_config.xml` while generation is on (Android's guide says the build then fails) [V DAC].

The generated file (AGP 9.4.1, release build) [X]:

```xml
<!-- res/xml/_generated_res_locale_config.xml (API 33–34) -->
<locale-config xmlns:android="http://schemas.android.com/apk/res/android" android:defaultLocale="en">
    <locale android:name="en"/>
    <locale android:name="uz-Cyrl"/>
    <locale android:name="ru"/>
    <locale android:name="uz"/>
</locale-config>
<!-- res/xml-v35/_generated_res_locale_config.xml: the same list without android:defaultLocale -->
```

Debug builds add `en-XA` and `ar-XB`. A hand-written file (same format, `res/xml/locales_config.xml`) is needed only if we want another order or a tag such as `uz-Latn`; then turn `generateLocaleConfig` off.

#### 1.4.3 What happens on each Android version [V bytecode of appcompat 1.8.0 and androidx.core 1.19.1]

- **API 33–37**: `setApplicationLocales` calls the framework's `LocaleManager.setApplicationLocales`. The system stores the choice, shows it in the phone's Settings, applies it to every context of the app (the Application context included) and recreates our activities. AppCompat reaches `LocaleManager` through a live AppCompat activity: called when none is alive, it silently does nothing (`getLocaleManagerForApplication` iterates the live delegates and returns null) — so call it only from the screen.
- **API 24–32**: AppCompat keeps the choice in memory, writes it to `files/androidx.appcompat.app.AppCompatDelegate.application_locales_record_file` (`AppLocalesStorageHelper` in androidx.core), reads it back synchronously when the first AppCompatActivity starts (Android's guide warns of a StrictMode disk-read report), overrides the configuration of every AppCompatActivity, recreates them and calls `LocaleList.setDefault`. The **Application context keeps the phone's language**: "the backward compatible APIs work with the AppCompatActivity context, not the application context, for Android 12 (API level 32) and earlier" [V DAC].
- **Upgrade from 12 to 13+**: on the first start on API 33+, AppCompat copies the stored choice into `LocaleManager` once (`syncLocalesToFramework`; it marks the metadata service component enabled as its "done" flag).
- **System language**: `setApplicationLocales(LocaleListCompat.getEmptyLocaleList())`; `getApplicationLocales()` then returns an empty list.

#### 1.4.4 How Compose picks up the change

The activity is recreated, so `setContent` runs again with new resources; `stringResource()` in Compose UI 1.12.1 reads `LocalResources` [V bytecode], and `pluralStringResource()` is available. Rules:

1. Do not declare `android:configChanges` for `locale` or `layoutDirection`; let the activity be recreated.
2. Never resolve screen text with the Application context or inside a ViewModel. Keep `@StringRes`/`@PluralsRes` ids and arguments in UI state and resolve them in composables (on API ≤ 32 the Application context would give the phone's language).
3. Recreating the activity must not lock the vault and must not lose an unsaved edit: the unlocked session and drafts live outside the activity (to be agreed with lock.md; ux.md: "Nothing the user types is ever lost"). Secret text fields are not kept in saved state (VERIFICATION.md V-C11); the language is changed from Settings, where no secret field is open.
4. For dates and numbers use `LocalConfiguration.current.locales[0]`, not `Locale.getDefault()` captured earlier.

#### 1.4.5 What the switch shows

A dialog with radio buttons (ux.md §5.18), in this fixed order, never re-sorted by the current language:

| Option | Label | Language tag passed to AppCompat |
|---|---|---|
| System language | translated: "System language" · "Tizim tili" · "Тизим тили" · "Язык системы"; second line: the language the app would use now, e.g. "Русский" [I] | empty list |
| Uzbek, Latin | **Oʻzbekcha** (U+02BB) | `uz-Latn` (reaches `values-uz` as `uz` does; build plan 6.1) |
| Uzbek, Cyrillic | **Ўзбекча** | `uz-Cyrl` |
| English | **English** | `en` |
| Russian | **Русский** | `ru` |

The order follows the user's own request (Uzbek Latin, Uzbek Cyrillic, English, Russian); ux.md lists English first — either is fine as long as it is fixed. Each name is written in its own language, from `values/donottranslate.xml`, and wrapped in a `SpanStyle(localeList = …)` of its own language so it is shaped and broken correctly. Ўзбекча, English and Русский are passed with the tags of the generated locale config, Oʻzbekcha as `uz-Latn`, which reaches `values-uz` the same way. Android 17's Settings › Apps › PasswordVault › Language marks `en`, `ru` and `uz-Latn` as the app's choice, never `uz`. It marks no Uzbek Cyrillic tag at all (neither `uz-Cyrl` nor the `uz-Cyrl-UZ` it sets itself when Ўзбекча is chosen there) and lists it first under All languages instead. Русский chosen there asks for a region and sets `ru-RU` [X, API 37, 2026-10-09]. Debug builds add "English (XA)" and "Arabic (XB)". A choice closes the dialog, like the other choice dialogs of Settings; Android recreates the activity in the new language on the screen the dialog was opened from.

```kotlin
enum class AppLanguage(val tag: String?) { SYSTEM(null), UZ_LATN("uz"), UZ_CYRL("uz-Cyrl"), EN("en"), RU("ru") }

fun setAppLanguage(lang: AppLanguage) = AppCompatDelegate.setApplicationLocales(
    lang.tag?.let(LocaleListCompat::forLanguageTags) ?: LocaleListCompat.getEmptyLocaleList())

fun currentAppLanguage(): AppLanguage {
    val l = AppCompatDelegate.getApplicationLocales()[0] ?: return AppLanguage.SYSTEM
    return when {
        l.language == "uz" && l.script == "Cyrl" -> AppLanguage.UZ_CYRL
        l.language == "uz" -> AppLanguage.UZ_LATN            // "uz", "uz-UZ" or "uz-Latn"
        l.language == "ru" -> AppLanguage.RU
        l.language == "en" -> AppLanguage.EN
        else -> AppLanguage.SYSTEM
    }
}
```

Because a Cyrillic-Uzbek reader may not find Settings in a language they read poorly, the first screen (ux.md §5.1) should carry the same switch behind a globe icon labelled "Til · Тил · Язык · Language" [I].

#### 1.4.6 Known gaps

- **Library texts in Ўзбекча are English.** appcompat 1.8.0, Compose material3 1.4.0, ui and foundation 1.12.1 and biometric 1.4.0-alpha07 ship `values-uz` and `values-ru` but no Cyrillic Uzbek [V AARs]. Their built-in texts (for example Material 3's accessibility labels, or the fingerprint dialog that androidx.biometric draws itself on API 24–27) therefore appear in English when the app is in Ўзбекча. Our visible texts are complete; check TalkBack in that language.
  - **Plan: overrides in the app (build-plan package 6.3).** An app resource with the same name and qualifier as a library resource wins when the resources are merged, and these libraries have no `values-b+uz+Cyrl` of their own, so the app supplies one file, `values-b+uz+Cyrl/strings_overrides.xml`. Package 6.3 lists the string names that reach the merged release APK from material3 (its accessibility labels and the other built-in texts our screens can show) and from androidx.biometric (the fingerprint dialog it draws on API 24–27), with `aapt2 dump resources` on the APK; gives each an Uzbek Cyrillic text, made from the library's own `values-uz` text by the rules of §2.5 and reviewed [N]; and marks each `tools:override="true"`, so that lint's `PrivateResource` check accepts a deliberate override of a library's private string. No code changes. The list is made again whenever one of these libraries changes version, and a name that no longer exists in the merged APK is removed. The other languages need nothing: the libraries ship `values-uz` and `values-ru`.
- **BiometricPrompt on API 28+ is drawn by the system**: our title, subtitle and button text appear in the app's language, the system's own hints in the phone's language.
- **App Bundles**: Google Play installs only the phone's languages as language splits, so switching in the app to another language would show English. If we ever publish an `.aab`, keep `bundle.language.enableSplit = false` (§1.1).
- **Backup**: the API 24–32 record file is an ordinary preference and may go with device transfer; on API 33+ the system keeps the choice.

## 2. The Uzbek Latin alphabet in 2026

### 2.1 The law in force today

The Law "Lotin yozuviga asoslangan oʻzbek alifbosini joriy etish toʻgʻrisida", No. 931-XII of 2 September 1993, Article 1 in the wording of Law No. 71-I of 6 May 1995, introduces "26 harf va 3 ta harflar birikmasidan iborat oʻzbek alifbosi" (26 letters and 3 letter combinations: Sh, Ch, Ng) plus the tutuq belgisi (apostrophe) [V lex.uz/docs/-112286]. The law fixes the shape, not a computer character: lex.uz's own copy prints the letters as ``O`o` `` and ``G`g` `` (U+0060 GRAVE ACCENT) in the alphabet table and as Oʻoʻ, Gʻgʻ (U+02BB) in the pronunciation column, and the tutuq as "(`)" [V raw HTML]. Cabinet of Ministers Resolution No. 61 of 10 February 2021 set measures for a complete transition to the Latin alphabet and mentions an improved alphabet, but did not change the letters [V lex.uz/docs/-5281850].

### 2.2 The 2026 reform: passed by parliament, not yet in force

- **7 July 2026**: the Legislative Chamber passed amendments replacing Gʻ gʻ → **Ğ ğ**, Oʻ oʻ → **Ö ö**, Sh sh → **Ş ş**, Ch ch → **Ç ç** and removing Ng from the alphabet list (the combination stays in spelling); the alphabet becomes "28 ta harf va bitta tutuq belgisi" [V kun.uz 2026-07-07, gazeta.uz 2026-07-09].
- **10 September 2026**: the Senate approved the law at its 19th plenary session and sent it to the President [V gazeta.uz, spot.uz 2026-09-10].
- **Not signed as of 2026-10-06** as far as I could find. Kun.uz (2026-09-13): if signed — expected by 21 October, Uzbek Language Day — "u rasman eʼlon qilinganidan keyin 6 oy oʻtib kuchga kiradi" (it enters into force six months after official publication) [V]. Earliest effect: about April 2027.
- **Transition**: documents, money and securities in the current alphabet stay valid; signs may stay until worn out; new school textbooks from 2027, all by 2031 [V Turkic Academy 2026-09-11]. For state information systems the Ministry of Digital Technologies plans automatic conversion of o', g', sh, ch to ö, ğ, ş, ç in databases; commentators warn of three alphabets in use at once [V spot.uz 2026-09-10].

Drafts since 2019 proposed other forms (ó, ǵ among them); the version that passed uses **ö ğ ş ç** — precomposed Latin letters (U+00F6, U+011F, U+015F, U+00E7) that every Android font already has (§2.6).

### 2.4 Decision for our screens

- **Write oʻ, gʻ, Oʻ, Gʻ with U+02BB MODIFIER LETTER TURNED COMMA and the tutuq belgisi with U+02BC MODIFIER LETTER APOSTROPHE.** Both are letters in Unicode (General Category Lm) [X ICU], so they stay inside words for selection, `\p{L}` and case mapping ("OʻZBEK" upper-cases correctly [X]); U+2018/U+2019 are quotation punctuation and the grave accent even splits words in ICU's word breaker [X]. This matches what the user reads on a current Android phone.
- **No ö ğ ş ç in the screens yet.** Review when the law is published, when it enters into force, and at every Android release; switch the whole `values-uz` file at once (never mixed), probably as a reviewed bulk conversion (oʻ→ö, gʻ→ğ, sh→ş, ch→ç, with a native check of words such as *Isʼhoq* where s and h are separate sounds) [N].
- **Encoding in `values-uz/strings.xml`**: type the characters themselves in UTF-8 (`Oʻchirish`, `maʼlumot`). Verified with aapt2 36.0.0 [X]:
  - `O'chirish` (ASCII apostrophe) → build error "unescaped apostrophe in string";
  - `O\'chirish` or `"O'chirish"` → compiles to U+0027, which is wrong for us;
  - `Oʻchirish` → U+02BB kept; `O&#x2BB;chirish` also works but is unreadable — don't.
  - A unit test enforces it (§5).
- **Brand names** keep their own spelling (Telegram, Gmail, Click, Payme, Google Password Manager).

### 2.5 Uzbek Cyrillic spelling

- Letters beyond Russian: Ў ў (U+040E/U+045E), Қ қ (U+049A/U+049B), Ғ ғ (U+0492/U+0493), Ҳ ҳ (U+04B2/U+04B3); ц щ ы ь only in loanwords (CLDR's auxiliary set for `uz_Cyrl`) [V].
- Correspondence with the Latin alphabet: oʻ ў, gʻ ғ, q қ, h ҳ, x х, sh ш, ch ч, j ж, y й, yo ё, yu ю, ya я, ʼ ъ; *e* is **э** at the start of a word or after a vowel (Экран, эълон) and **е** elsewhere (Бекор, Версия); *ye* at the start is **е** (Ер). ICU's own `uz_Latn-uz_Cyrl` transliterator gets e wrong ("Ўзбэкистон", "Тэлэграм") [X], so do not use it to produce strings.
- **Loanwords follow today's official Cyrillic practice, not the older habit of keeping the Russian spelling (пароль)** [I]: lex.uz's sign-in page says "Паролингизни", "Паролни"; my.gov.uz's instructions say "парол", "паролингиз" [V]. So Парол, Пароллар; Лицензия keeps ц.
- The Cyrillic column of the glossary was produced from the Latin column by these rules with a script, checked by hand, and compared with Cyrillic attested in GNOME's Uzbek Cyrillic translations and Microsoft's Uzbek Cyrillic terminology where they exist [X] [N].
- Quotation marks “ ” as in Latin Uzbek (CLDR `uz_Cyrl` inherits them; my.gov.uz writes “Кириш”, “Кейинги”) [V].

### 2.7 Search and sorting

ux.md §5.11 promises that "o'zbek", "oʻzbek" and "ўзбек" find the same entry. The rule that makes this true, and also covers ö ğ ş ç, Russian Cyrillic and ё:

1. Normalise to NFC and lower-case with `Locale.ROOT`.
2. Delete every apostrophe-like mark: ' ` ´ ‘ ’ ‛ ′ ʹ ʻ ʼ ʽ ʾ ʿ (U+0027 U+0060 U+00B4 U+2018 U+2019 U+201B U+2032 U+02B9 U+02BB U+02BC U+02BD U+02BE U+02BF).
3. Map the reform letters: ö→o, ğ→g, ş→sh, ç→ch.
4. Map Cyrillic to Latin: а a, б b, в v, г g, д d, е e (ye at the start or after a vowel, ъ or ь), ё yo, ж j, з z, и i, й y, к k, л l, м m, н n, о o, п p, р r, с s, т t, у u, ф f, х x, ц ts, ч ch, ш sh, щ sh, ъ —, ы i, ь —, э e, ю yu, я ya, ў o, қ q, ғ g, ҳ h.
5. Remove remaining accents (NFD, drop marks); turn everything that is not a letter or digit into one space.
6. Match if the folded query occurs in the folded name; also try both with ё replaced by е, because Russian writers often type е for ё (Семёнов / Семенов).

Examples, all passing in the reference implementation [X]: o'zbek, oʻzbek, o‘zbek, o’zbek, o`zbek, Oʼzbek, Özbek, ўзбек, ЎЗБЕК → `ozbek`; gʻalaba, Ğalaba, ғалаба → `galaba`; maʼlumot, ma'lumot, маълумот → `malumot`; Şifokor, шифокор → `shifokor`; Çorsu, Чорсу → `chorsu`; Сбербанк → `sberbank`; Телеграм → `telegram`; Ёқут → `yoqut`; Ер → `yer`; Ҳамкорбанк → `hamkorbank`; "Ўзбекистон почтаси" matches "oʻzbek" and "pochta"; "Семёнов" matches "семенов"; "Alyona" matches "алёна". Russian x/kh spellings ("Хамкорбанк" written by a Russian speaker) still do not match "Hamkorbank" [I — acceptable; mention in help]. The function uses only `java.text.Normalizer` and string operations, so it runs on API 24 (ICU's `Transliterator` would need API 29 [V], and its Uzbek Latin→Cyrillic direction is wrong anyway).

**Sorting** (A–Z): use `android.icu.text.Collator` for the app's language on a copy of the name in which ' ‘ ’ ` ʼ after o, g, O or G are replaced by ʻ. ICU 78.1's Uzbek order already treats those variants alike and puts Oʻ, Gʻ, Sh, Ch after Z, as the alphabet does; Russian order puts Cyrillic before Latin [X]. In the Russian and English orders, however, ' and ‘ are ignorable punctuation while ʻ is a letter, so the same name typed with different marks lands in different places ("O'zbekiston pochtasi", "O‘zbekneftgaz", "Oʻzbekiston banki" in that order); after the replacement the order is stable in every language [X].

```kotlin
private val OG_MARK = Regex("(?<=[oOgG])['‘’`ʼ]")
fun sortKey(collator: android.icu.text.Collator, name: String) = collator.getCollationKey(OG_MARK.replace(name, "ʻ"))
```

Reference implementation of the search key (Kotlin, API 24; the same 61 cases pass as JUnit tests with Kotlin 2.4.20 [X]):

```kotlin
import java.text.Normalizer
import java.util.Locale

/** Search key for account names: Uzbek Latin with any apostrophe, the 2026 letters, Uzbek/Russian Cyrillic, English. */
object SearchFold {
    private const val APOSTROPHES = "'`´‘’‛′ʹʻʼʽʾʿ"
    private val CYR = mapOf(
        'а' to "a", 'б' to "b", 'в' to "v", 'г' to "g", 'д' to "d", 'ж' to "j", 'з' to "z", 'и' to "i", 'й' to "y",
        'к' to "k", 'л' to "l", 'м' to "m", 'н' to "n", 'о' to "o", 'п' to "p", 'р' to "r", 'с' to "s", 'т' to "t",
        'у' to "u", 'ф' to "f", 'х' to "x", 'ц' to "ts", 'ч' to "ch", 'ш' to "sh", 'щ' to "sh", 'ъ' to "", 'ы' to "i",
        'ь' to "", 'э' to "e", 'ю' to "yu", 'я' to "ya", 'ё' to "yo", 'ў' to "o", 'қ' to "q", 'ғ' to "g", 'ҳ' to "h",
        'ö' to "o", 'ğ' to "g", 'ş' to "sh", 'ç' to "ch",
    )
    private const val VOWELS_ETC = "аеёиоуўэюяыъьaeiou"
    private val MARKS = Regex("\\p{M}+")
    private val NON_WORD = Regex("[^\\p{L}\\p{N}]+")

    fun fold(s: String): String {
        val n = Normalizer.normalize(s, Normalizer.Form.NFC).lowercase(Locale.ROOT)
        val out = StringBuilder(n.length + 8)
        var prev = ' '
        for (c in n) {
            if (c in APOSTROPHES) continue
            out.append(
                when {
                    c == 'е' -> if (!prev.isLetter() || prev in VOWELS_ETC) "ye" else "e"
                    else -> CYR[c] ?: c.toString()
                }
            )
            prev = c
        }
        val noMarks = MARKS.replace(Normalizer.normalize(out, Normalizer.Form.NFD), "")
        return NON_WORD.replace(noMarks, " ").trim()
    }

    /** Russian writers often type е for ё; try both. */
    private fun variants(s: String): List<String> {
        val lower = s.lowercase(Locale.ROOT)
        return if ('ё' in lower) listOf(fold(s), fold(lower.replace('ё', 'е'))) else listOf(fold(s))
    }

    fun matches(name: String, query: String): Boolean =
        variants(query).filter { it.isNotEmpty() }.any { q -> variants(name).any { it.contains(q) } }
}
```

## 4. Writing rules

### 4.1 Plurals

CLDR 48 rules, which Android applies through ICU (checked with ICU 78.1 and with the Android 7.0 version, ICU 56.1 [X]):

| Language | Categories | Integers |
|---|---|---|
| English | one, other | 1 → one; everything else → other |
| Uzbek (both scripts) | one, other | 1 → one; everything else → other |
| Russian | one, few, many, other | one: ends in 1 but not 11 (1, 21, 101); few: ends in 2–4 but not 12–14 (2, 3, 22); many: 0, 5–20, 25–30, 111…; other: only fractions (1.5) |

- Uzbek nouns stay singular after a number, usually with the counter *ta*: "1 ta hisob", "5 ta hisob". Both items carry the same text; they must still both exist.
- Russian needs all four items; `other` is never chosen for a whole number, and AOSP fills it with the genitive singular (KG `kg_too_many_failed_attempts_countdown_seconds`: few "секунды", many "секунд", other "секунды") — do the same.
- Lint's `MissingQuantity` catches a Russian `<plurals>` without few and many [X]; it is an error by default.
- Pass the number twice: `pluralStringResource(R.plurals.accounts_count, n, n)`.
- Zero gets its own string ("No accounts yet"), never a plural item.

```xml
<!-- values/strings.xml -->
<plurals name="accounts_count">
    <item quantity="one">%d&#160;account</item>
    <item quantity="other">%d&#160;accounts</item>
</plurals>
<!-- values-uz/strings.xml -->
<plurals name="accounts_count">
    <item quantity="one">%d&#160;ta hisob</item>
    <item quantity="other">%d&#160;ta hisob</item>
</plurals>
<!-- values-b+uz+Cyrl/strings.xml -->
<plurals name="accounts_count">
    <item quantity="one">%d&#160;та ҳисоб</item>
    <item quantity="other">%d&#160;та ҳисоб</item>
</plurals>
<!-- values-ru/strings.xml -->
<plurals name="accounts_count">
    <item quantity="one">%d&#160;аккаунт</item>
    <item quantity="few">%d&#160;аккаунта</item>
    <item quantity="many">%d&#160;аккаунтов</item>
    <item quantity="other">%d&#160;аккаунта</item>
</plurals>
```

The plural rows of the glossary give the other counted phrases (attempts left, seconds, minutes, used by N accounts). Russian prepositional phrases change too: "используется в 1 аккаунте", "в 3 аккаунтах", "в 5 аккаунтах".

### 4.2 Typography

| Rule | English | Uzbek (Latin and Cyrillic) | Russian |
|---|---|---|---|
| Quotation marks | “ ” | “ ” (CLDR; AOSP Uzbek uses “ ” 49 times in Settings; my.gov.uz “Кириш”) | « », inside „ “ (CLDR `ru`) |
| Ellipsis | … (U+2026) | … | … , no space before it |
| Apostrophe letters | — | ʻ U+02BB in oʻ gʻ, ʼ U+02BC for the tutuq; Cyrillic ъ | — |
| Number + word or unit | no-break space U+00A0 (`&#160;` in XML; aapt2 keeps it as U+00A0 [X]) | `30&#160;soniya`, `%d&#160;ta` | `30&#160;секунд` |
| Ranges | en dash: A–Z, 0–9, 8–64 | same | same; sentence dash: " — " |
| Digit grouping and decimals | only via ICU | 1 234 567,89 (U+00A0) | 1 234 567,89 (U+00A0) |

Notes:
- Russian: AOSP itself uses straight quotes `\"` (748 times in Settings, never « ») and Microsoft's 2022 Russian guide asks for straight quotes in software; we use « » because it is the Russian typographic norm (CLDR) and needs no escaping in XML. Either is acceptable; one style throughout is what matters [I].
- Russian ё: write it always (Mozilla does; AOSP and Bitwarden are inconsistent — AOSP has "Тёмная тема" but "Надежные сертификаты") [X]. Search treats ё and е as equal (§2.7).
- Russian dates on the screen end in a period ("7 окт.", "7 окт. 2026 г.": ICU's own format), so a translation never puts a date placeholder at the end of a sentence ("…%1$s." shows "окт.."); the date stands inside the sentence or before a comma or question mark. A dash between words takes a no-break space before it ("слово&#160;— слово"), so that no line starts with a dash. (Found in round R6 by 6.4b; applied by 6.4a and 6.4b.)
- Long Russian words may carry a soft hyphen U+00AD where a narrow label needs it, as AOSP does (`Конфиденциаль&#173;ность` in XML; aapt2 turns `&#173;` into U+00AD [X]); Android has Russian hyphenation patterns but none for Uzbek (`external/hyphenation-patterns`: `laboratory50/ru`, no `uz`) [V].
- Never build a date, number or list by hand; never put a space inside "PIN-код".

### 4.3 Capitalisation

- **Sentence case in every language** for titles, buttons, menu items and labels: "Ekran qulfi", "Экран қулфи", "Блокировка экрана", "Screen lock" [V AOSP]. No Title Case and no all-caps buttons (Material 3 does not use caps).
- Uzbek capitalises only the first word and proper names (Microsoft Uzbek guide: "capitalize only when you have to"); oʻ and gʻ at the start of a sentence are "Oʻ", "Gʻ" — U+02BB has no case form [X].
- Russian follows the same rule (Microsoft Russian guide 4.1.3); product names keep their case.

### 4.4 Formality, tone and grammar

- **Uzbek: polite *siz*, written in lower case inside a sentence, and usually left out because the verb ending carries it**: "PIN kodni kiriting" (enter the PIN), "Qayta urining". AOSP has *siz/sizning…* in lower case 56 times and never capitalised [X]; Microsoft's 2011 guide asked for "Siz" with a capital — we follow Android. Questions to the user use the polite past "-dingizmi?" ("PIN kodni unutdingizmi?"); confirmations use the impersonal "-ilsinmi?" ("Bu hisob oʻchirilsinmi?", as AOSP "…oʻchirilsinmi?").
- **Russian: *вы* in lower case** (AOSP, Firefox, Bitwarden, Proton Pass and KeePassDX: 0 capitalised "Вы" inside sentences [X]); imperatives in the polite form ("Введите", "Коснитесь"); short messages impersonal or in the neuter ("Сохранено", "Скопировано", "Удалено") so they do not depend on the gender of a noun; when a noun is named, agree with it ("Пароль скопирован", "Запись сохранена").
- **Plain words** (ux.md §1): no "KDF", "entropy" or "vault key" in any language; Uzbek and Russian loanwords only where Android uses them (PIN kod, fayl, parol, biometriya).
- **Placeholders**: positional (`%1$s`), full sentences, never concatenation. Uzbek suffixes must not be glued to a placeholder that can be a brand or user text; add a noun ("%1$s saytida", "“%1$s” hisobi") or a hyphen. Russian cannot decline a placeholder: put it after a noun in the nominative ("в приложении «%1$s»", as AOSP's "приложением \"%1$s\"").
- Every string gets a translator comment (where it appears, maximum length if any).

### 4.5 Text expansion and layout

Measured on 11,400 AOSP strings that exist in English, Uzbek and Russian (Settings, framework, SystemUI, SettingsLib, keyguard, DocumentsUI) [X]:

| English length | n | Uzbek / English median · 90th pct · max | Russian / English median · 90th pct · max |
|---|---|---|---|
| 1–10 chars | 2,769 | 1.25 · 2.33 · 9.50 | 1.29 · 2.60 · 8.00 |
| 11–20 | 3,392 | 1.27 · 1.91 · 3.40 | 1.29 · 2.00 · 3.63 |
| 21–40 | 2,992 | 1.21 · 1.64 · 4.35 | 1.22 · 1.70 · 3.62 |
| 41–80 | 1,462 | 1.15 · 1.48 · 2.23 | 1.15 · 1.54 · 2.43 |

Words are longer too: median word length 4 characters in English, 7 in Uzbek and Russian; 99th percentile 13 / 16 / 15; examples "bildirishnomalaringizni" (23), "faolsizlantirilmaguncha" (23), "телекоммуникационными" (21).

Layout rules:
1. No fixed widths for text; buttons use `widthIn(min = …)`, and button rows become a vertical stack (`FlowRow`) when they do not fit.
2. Labels may take two lines; a field's label of two lines moves above its box (`FieldLabel`). Screen titles stay within about 20 characters in every language — check the glossary forms of every title; a title that does not fit beside the top bar's buttons moves under them and wraps (`VaultTopBar`, build plan 6.2).
3. Truncate with an ellipsis only where the full text is reachable elsewhere (list rows → detail screen); never truncate a warning or a button.
4. Russian text: `hyphens = Hyphens.Auto` in the typography. Uzbek cannot be hyphenated by Android, so a long Uzbek word moves to the next line whole — leave room. The layout probe of `tools/emu/layout/` counts a word split across two lines as a fault, so a walk in Russian would report the hyphenated words; today it walks the pseudo-locales only.
5. The bottom bar's three labels (Parollar / Xavfsizlik / Sozlamalar; Пароли / Безопасность / Настройки) must fit at 320 dp width and 200 % font scale or be shortened [N]. The three take one size, the largest at which each word of all three fits on its line (`FittedText` with `alongside`; `LongTextLayoutTest`).
6. In the English strings a no-break space (U+00A0, `&#160;`) joins a number or a number placeholder to its unit or the word that goes with it ("24&#160;hours", "%1$d&#160;accounts"; §4.2, build plan 6.2). Translations keep a no-break space between the number and the word that goes with it ("%d&#160;ta", "%d&#160;аккаунтов"), so that the two never part at the end of a line.

### 4.6 Dates, times and numbers

Use `android.icu.text.DateFormat.getInstanceForSkeleton(skeleton, locale)`, `RelativeDateTimeFormatter`, `MeasureFormat` and `NumberFormat` (all API 24 [V `api-versions.xml`]) with `locale = LocalConfiguration.current.locales[0]`. Store times as UTC instants; show them in the phone's time zone (Uzbekistan: Asia/Tashkent, UTC+5, no daylight saving). Follow the phone's 12/24-hour setting (`android.text.format.DateFormat.is24HourFormat`); all three of our non-English languages default to 24 hours.

ICU 78.1 (Android 17), 6 October 2026 14:05 in Tashkent [X]:

| Skeleton or API | en | uz | uz-Cyrl | ru |
|---|---|---|---|---|
| `yMd` | 10/6/2026 | 06/10/2026 | 06/10/2026 | 06.10.2026 |
| `yMMMd` | Oct 6, 2026 | 6-okt, 2026 | 6 окт, 2026 | 6 окт. 2026 г. (U+202F before г.) |
| `yMMMMd` | October 6, 2026 | 6-oktabr, 2026 | 6 октябр, 2026 | 6 октября 2026 г. |
| `jm` (time) | 2:05 PM (U+202F before PM) | 14:05 | 14:05 | 14:05 |
| relative | yesterday · 5 minutes ago | kecha · 5 daqiqa oldin | кеча · 5 дақиқа олдин | вчера · 5 минут назад |
| number 1234567.891 | 1,234,567.891 | 1 234 567,891 | 1 234 567,891 | 1 234 567,891 |
| percent 0.85 | 85% | 85% | 85% | 85 % |

Android 7.0 has ICU 56.1 [V `external/icu` `uvernum.h`], whose data differ in detail: "6-Oktabr, 2026", "2026 Окт 6" (uz-Cyrl), Russian short date "06.10.26" [X ICU4J 56.1]. That is correct behaviour (the phone's own format) — screenshot tests on old versions must not expect Android 17's text. Durations in settings ("After 30 seconds") come from our plural strings, not from `MeasureFormat`, so the wording matches the rest of the screen. For the same reason a relative time of less than a minute, before or after, is our string `common_just_now` ("just now", translated with the others), not ICU's "now" ("hozir", "сейчас"), which reads wrong inside "Password changed …" and "Last backup: …" (build plan §12, `w5-carry`); from a minute on, ICU's words of the table above. On a screen the spaces inside a date are no-break spaces (U+00A0), so that a date never breaks across two lines ("Oct / 7, 2026" in a title): `Formatters` puts them into `date`, `dayMonth` and the date part of `dateTime`, where the line may still break between the date and the time (build plan §12, `w5-carry`).

## 6. Consistency with ux.md and open questions

- **ux.md §9 and §5.18 list three languages** and call Uzbek Cyrillic "only on request"; the user asked for it, so the language dialog there should list Ўзбекча too.
- ux.md asks for plain words ("locked file", "unprotected file"); the glossary gives those and the technical words (encrypted, not encrypted) for help pages.
- ux.md says "recently used" is not tracked in version 1; the glossary term is reserved for later.
- ux.md's "System default" option is labelled "System language" here, because that is Android's own label (Set `preference_of_system_locale_title`: "Tizim tili", "Язык системы").
- ux.md §9 cites Wikipedia for U+02BB as "the official character"; the law itself fixes only the shape (§2.1). U+02BB is still the right choice, for the reasons in §2.4.
- ux.md §9 estimates "20–40 % longer"; the AOSP measurement in §4.5 agrees on the median (+20–29 %) but shows that one short label in ten more than doubles.
- formats.md writes numbers and dates *in files* with `Locale.ROOT`; that is right for files and does not apply to screens, which follow §4.6. Its export warnings ("This file will not be protected") use the glossary's "unprotected" family: Himoyalanmagan / Ҳимояланмаган / Незащищённый.
- Open: the 2026 reform (signature, publication date, Android's own switch); the Uzbek words for password strength ("Parol kuchi", "Kuchli"), which have no product source [N]; whether to show the system-language hint line in the switch; whether Pixel, Samsung and Xiaomi actually offer Ўзбекча as a phone language (needs real devices).
